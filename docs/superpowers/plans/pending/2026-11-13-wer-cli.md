# WER CLI cho micro và file audio — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Chỉ triển khai khi người dùng yêu cầu; lượt hiện tại chỉ lập plan.

**Goal:** Có script local đo WER/CER với file WAV hoặc bản thu micro và TXT chuẩn; so sánh off/DeepFilterNet3 trên cùng audio, xuất đối chiếu lỗi tái lập được.

**Architecture:** CLI Python gọi trực tiếp runtime Zipformer/Silero/DeepFilterNet hiện có. Scorer tách khỏi capture/inference, reference không đi vào decoder. Hai pipeline batch và replay session có report riêng; không cần HTTP hoặc UI.

**Tech Stack:** Python 3.12 trong `.venv-stt`; NumPy/SoundFile/SciPy hiện có; JiWER 4.0.0; sounddevice 0.5.6 cho micro; pytest.

**Spec:** `docs/superpowers/plans/pending/2026-11-13-wer-cli-design.md`.

## Global Constraints

- Chỉ CLI; không thêm giao diện, endpoint hay sửa luồng khám/micro hiện tại.
- Local inference, không cloud; reference không làm hotwords/prompt và không tự sửa output theo đáp án.
- Profile `vi-whitespace-v1`; không quy đổi số/tên thuốc/phủ định trong metric chính; N=0 là input invalid.
- Thu một lần cho A/B; chuẩn hóa PCM16 mono 16 kHz một lần; hotwords/config snapshot bất biến giữa các mode.
- Mặc định denoise `off`; chỉ chạy cả hai khi chỉ định `--denoise both`; chạy tuần tự để hạn chế RAM.
- Không thêm giới hạn file 30s; micro dùng thời lượng dương do người dùng chỉ định.
- Không ghi audio mặc định. Report/transcript chỉ xuất khi có output-root; save-audio là lựa chọn riêng.
- Không tự bật backend; không commit thay đổi có sẵn của người dùng. Mỗi commit mới, nếu được thực hiện, phải có GitNexus detect_changes hợp lệ ngay trước đó.

## Files và interfaces

Tạo mới, mỗi file một trách nhiệm:

| File | Trách nhiệm |
| --- | --- |
| `stt/wer_metrics.py` | `normalize_vi(text: str) -> list[str]`; `score_text(reference: str, hypothesis: str) -> dict`; `aggregate_scores(scores: list[dict]) -> dict` |
| `stt/wer_audio.py` | `read_wav(path: Path) -> tuple[CanonicalAudio, dict]`; `canonicalize(samples: ndarray, sample_rate: int) -> CanonicalAudio` |
| `stt/wer_capture.py` | `list_input_devices() -> list[dict]`; `capture_once(seconds: float, device: str | int | None) -> tuple[CanonicalAudio, dict]` |
| `stt/wer_runner.py` | `run_comparison(audio: CanonicalAudio, config: RunConfig) -> list[dict]`; `RunConfig` frozen dataclass, không có reference |
| `stt/wer_report.py` | `build_report(reference: str, runs: list[dict], metadata: dict) -> dict`; `export_report(report: dict, root: Path, audio: CanonicalAudio | None = None) -> Path` |
| `stt/wer.py` | `main(argv: list[str] | None = None) -> int`; subcommands `file`, `mic`, `score`, `devices` |
| `stt/requirements-wer.txt` | Pin `jiwer==4.0.0`, `sounddevice==0.5.6`; SciPy `>=1.11,<2`, dùng môi trường STT sẵn có |
| `stt/tests/test_wer_{metrics,audio,capture,runner,report,cli}.py` | Test từng contract; fake device/engine khi không cần model thật |
| `docs/WER.md` | Cài đặt, chạy lệnh, chuẩn chép, đọc report, diagnostic checklist |

`RunConfig`: `pipeline: Literal['batch','session']`, `denoise: Literal['off','deepfilternet3','both']`, `hotwords_path: Path`, `chunk_frames: int = 80000`. Không expose boost/VAD tuning trong CLI phiên bản đầu; giữ đúng baseline hiện tại.

Mỗi run dict: `mode`, `pipeline`, `status` (`ok|failed`), `transcript` nếu thành công, `error_code` nếu lỗi, `audio_sha256`, `config_fingerprint`, `timings`. Metadata chi tiết theo spec; JSON report `schema_version=1`. Scorer thêm `N,S,D,I,wer,cer,alignment`; `wer/cer` ở thang 0..n, console/Markdown hiển thị phần trăm.

## Task 4: CLI, corpus và hướng dẫn sử dụng

**Files:** tạo `stt/wer.py`, `test_wer_cli.py`, `docs/WER.md`; cập nhật mục WER trong `docs/STT.md`, changelog sau khi có implementation.

**Interfaces/flags:**

- `file --audio PATH --reference PATH --consent-local [--pipeline batch|session] [--denoise off|deepfilternet3|both]`.
- `mic --seconds FLOAT --reference PATH --consent-local [--device ID_OR_NAME] [--pipeline batch|session] [--denoise ...]`.
- `score --reference PATH --hypothesis PATH`; `devices`.
- `--output-root PATH` tùy chọn cho file/mic/score, `--save-audio` chỉ file/mic và phải có output-root. Output-root phải nằm trong `.tmp/wer` đã resolve; thư mục con run-ID duy nhất.
- `--hotwords-file PATH` cho file/mic, mặc định runtime hiện hành (ưu tiên env giống load_hotwords). Defaults: pipeline=batch, denoise=off. Mic examples chỉ định session rõ ràng.
- `corpus --manifest PATH --consent-local --pipeline ... --denoise ...`: JSONL `{"id":"...","audio":"...wav","reference":"...txt"}`; relative path tính từ manifest; id unique, thiếu cặp báo lỗi trước load model. Aggregate theo cấu hình và theo từng sample boundary; partial corpus có count failed, exit=1, không giấu mẫu lỗi.
- Exit 0: mọi run yêu cầu hoàn thành, kể cả WER cao; 1: runtime/capture/mode/corpus lỗi; 2: input invalid/thiếu consent. Không lấy ngưỡng WER làm tiêu chí pass chức năng ngầm định.

- [ ] Test argparse/consent trước mở device/load model, lazy import `score` không đòi sounddevice/model, `devices` không thu; capture được gọi đúng 1 lần khi both.
- [ ] Test không có output-root thì chỉ summary, không transcript/WAV xuất đĩa; save-audio thiếu output-root bị từ chối trước capture; artifact traversal/overwrite từ chối; stdout/stderr không dump nội dung nhạy cảm khi lỗi.
- [ ] Test corpus weighted totals, id trùng/missing pair trước inference, group pipeline riêng, mode failed không rơi khỏi denominator âm thầm. Với aggregate trên tập con thành công, phải ghi rõ coverage và không báo là toàn corpus. Test A chỉ off thành công, B chỉ on thành công → không có paired delta; thêm C cả hai thành công → delta chỉ trên C, comparison=partial, paired_count=1 và excluded IDs gồm A/B.
- [ ] Run `.venv-stt/Scripts/python.exe -m pytest stt/tests/test_wer_cli.py -q` → FAIL trước implement; implement entry point/exports theo các contract; run lại → PASS.
- [ ] Viết hướng dẫn các lệnh dưới, giải thích micro native khác browser, session là replay, chuẩn chép lời thực nói, thu sạch/nhiễu và bảo quản report local. Không thay defaults ứng dụng.
